# AI 自主读取文件（ChatGPT / DeepSeek）

打开项目的方式仍然是 `npm run dev`。选择 ChatGPT 或 DeepSeek 并开启终端模式后，可以直接说：

> 先找出项目的入口文件和工作区截图，再读取相关源码并查看截图，解释当前布局。

`read_files` 读取指定路径的完整文件，并统一作为附件上传到当前平台会话，文本和源码也走附件。仅发送附件，消息正文为空；路径、文件名、文件大小、读取错误和内部请求标记只保留在本地执行记录或诊断日志。读取全部失败时，不向网页提交空消息。注入段落仅描述工具用途、调用格式、参数、返回内容和限制，不规定搜索顺序或阅读策略。手动模式点击待处理项的「读取」；自动模式自行读取并上传。目前支持 ChatGPT 和 DeepSeek。

系统提示词和工具提示词统一写在 [src/shared/types.ts](../src/shared/types.ts) 代码文件中；工具内容由 `readFilesToolPrompt` 定义，`toolPromptForPlatform` 根据平台选择并填入平台名称。`fileReadingPlatform` 统一控制提示词、请求处理和上传开放范围。修改代码并重新构建、重启应用后，应用使用新内容；安装包包含构建时的提示词，不依赖运行时的源码目录。

侧栏的「查看注入的系统提示词」显示基础终端说明、执行环境和用户补充；旁边的「查看注入的工具提示词」只显示当前平台启用的工具说明。两个视图均支持复制和查找；未适配的平台显示暂无工具提示词。预览和实际注入共用主进程生成的内容，实际发送顺序仍为「内置终端说明 → 工具说明 → 用户补充 → 本次输入」。

```json
{
  "type": "read_files",
  "files": [
    {"path": "src/main/embed.ts"},
    {"path": "docs/screenshots/workspace.png"}
  ],
  "description": "读取发送逻辑和截图"
}
```

- 文件对象只有 `path`。上传完整原文件，保留原始字节，不转码、不截取行数，也不将正文写入消息。旧请求中的 `mode`、`start_line`、`max_lines`、`encoding` 字段会被忽略，统一上传完整附件。
- 每次 1–5 个非空普通文件；单个最大 20 MiB，附件合计最大 25 MiB。这是应用限制，不代表网页账户或模型的附件额度。文件类型是否接受由网页决定。本地读取结果显示大小为 MB，保留两位小数。
- 相对路径绑定检测请求时的模型终端工作目录；SSH 会话从绑定主机经 SFTP 读取。读取结果不会自动转到本机。
- 附件先生成独立快照，再交给当前平台原生文件输入框。不会改动源文件。图片发送成功后保存到应用对话记录；文档保留文件名和读取记录。
- DeepSeek 的实际文件入口按扩展名接收附件。对于 `.gitconfig`、`.bashrc`、`Makefile` 等无扩展名文件，若完整快照是有效 UTF-8 文本且没有二进制控制字符，仅给临时附件名加上 `.txt`（例如 `.gitconfig.txt`），并使用 `text/plain` MIME。文件字节、编码、原路径和源文件保持原样；识别时的解码结果不发送。ChatGPT 保留原文件名，二进制或未确认编码的文件不采用此兼容。
- 文件输入框优先在当前输入区域内查找；多个入口都能接收目标文件时，选择唯一不限制文件类型的通用附件入口。没有通用入口且候选仍有多个时，保留失败状态，避免选错入口。文件选择前刷新输入框时使用同一规则。
- 附件检查范围沿输入框祖先最多向上检查 8 层，覆盖工具栏或原生表单外的附件卡片；遇到文字消息、模型答复或完整用户消息容器就停止。找到表单也继续检查安全的外层输入区域，避免网页上传完成后移动卡片导致识别失败。保留可点击卡片、`contenteditable="false"` 只读卡片里的文件名及 title／aria-label；只移除可编辑区域和原生输入值，防止把草稿或历史消息当作附件预览。
- 文件名匹配兼容 Unicode／空白归一化，以及当前批次中能唯一定位到文件的长前缀省略号；省略部分至少包含 12 个可见前缀字符，共享前缀有歧义或批次缺少文件时继续等待。发送前与新消息确认使用同一规则，同时仍需上传完成、发送按钮启用及所有文件均有证据。
- 手动／自动模式、暂停、发送延迟、结束任务、中断均作用于读取流程。恢复后的历史读取请求不会自动上传。
- 用户已有文字或附件草稿时不覆盖。结果保留在执行记录，清理草稿后可点「重试回传」。当前进程内重试复用快照；重启后未发送的快照不自动重读，需发起新请求。
- 已点击发送但未确认的记录显示「提交待确认」，不会自动重复点击。请先检查网页里是否已经出现该消息。确认等待结束后释放页面的等待状态，继续检测后续模型回复；不会因这一条记录未确认而阻塞整条自动执行流程。
- 发送确认通过新用户消息中的图片预览／文档文件名及草稿清空状态判断；请求 token 只用于本地关联，不写入消息正文。旧消息重新渲染不会作为发送成功依据。
- ChatGPT 的附件确认直接查询 `[class~="group/user-message"][data-chatgpt-search-unit-key]` 完整用户消息容器，将嵌套节点归并到这个容器，并用其 `data-chatgpt-search-unit-key` 比较提交前后的消息。2026-10-05 用户驱动探针确认：文件卡片与空的文字单元是该容器中的兄弟节点，文字单元的 `data-content-search-unit-key` 在发送时会消失、随后重建；不能依赖文字单元出现来确认纯附件消息。完整容器内检查图片及正文／title／aria-label 中的文件名，网页加上的 `(1)` 后缀仍能匹配原文件名。没有完整容器时才回退到旧的用户文字单元及有边界的祖先范围。模型回复声称已上传、旧消息中有同名文件都不作为成功依据。此范围和标识仅用于本次附件确认，不改变终端命令使用的消息选择器与持久消息 ID。
- DeepSeek 额外识别 `.ds-button--disabled` 的自定义按钮禁用状态。图片也允许通过完整文件名卡片确认；同时要求新用户消息、附件证据存在且草稿清空。数字行标识与提交前的最大位置比较；非数字标识或缺少数字基线时，与提交前保存的标识集合比较。`data-virtual-list-item-key` 仅用于本次发送的临时比较，不作为命令的持久消息 ID。同一个 DOM 行被虚拟列表复用时仍需新的标识，旧行重新渲染不能确认发送。确认时排除包含 `.ds-think-content` 的模型思考行，优先匹配含本次附件的用户行，避免空占位行挡住实际消息。成功确认及确认等待结束都会重新安排命令检测，覆盖下一条回复已经生成的情况；原有命令去重规则保留。
- 上传时绑定当前平台、会话和本机／SSH 主机；切换后停止回传。上传器共用 [src/main/page-files.ts](../src/main/page-files.ts)，页面差异留在 [src/shared/platforms.ts](../src/shared/platforms.ts) 的适配器里。

## 回传诊断日志

实际附件回传会自动将阶段日志同步追加到 `%TEMP%\gpt-login-diag\<platform>-file-send-<timestamp>-<pid>.log`，平台前缀为 `chatgpt` 或 `deepseek`，不需要开启 `DSH_APP_LOG`。日志按请求 token 区分，包含平台、文件数量／MIME／大小、入口识别结果、文件输入框的 accept／multiple／disabled、CDP 步骤、上传网络状态、页面预览和按钮状态，以及最终失败原因；不记录消息正文、文件内容、图片字节或 cookie。

`finish` 行中的 `stage` 和 `reason` 指出具体停止位置，例如 `begin / no-file-input` 是文件输入框发现失败或入口候选不唯一，`begin / unsupported-file-type` 是入口存在但不接受本次文件类型，`file-selection / exception` 是选择文件失败，`upload-wait / upload-ready-timeout` 是上传或页面就绪未确认。文件名兼容会在本地执行记录中显示，阶段日志仅记录 `textNameAlias` 布尔值。日志用于定位失败阶段，不能单凭页面预览认定附件发送成功。

文件名一直未识别时，还会周期性记录 `page-diagnostics`：输入框各级祖先的深度、是否为表单、当前选定范围、是否遇到对话消息、控件／图片数量以及正文／标签的文件名匹配数量。`nameEvidence` 按文件序号记录名称长度和匹配方式（完整、归一化、省略、图片或未匹配），用于区分缺少卡片与文件名变化。仅记录布尔值、数量和匹配类型，不记录卡片文字、文件名、标签正文或聊天内容。

`confirm-state` 还记录是否有行标识、是否属于提交前已有消息、基线标识数量、是否有数字基线及用户行数量，帮助区分数字／非数字标识与旧消息。`release-result` 记录上传器结束时页面状态释放调用的结果，便于排查后续命令检测被阻塞。实际行标识值和消息正文不会写入这些诊断字段。

新用户消息已经识别，但其中附件未识别时，`confirmation-diagnostics` 会记录 `userAttachmentAncestors`：用户消息各级祖先的深度、选定范围、图片数及文件名匹配数，并标出遇到其他消息、模型答复或输入框的边界。只记录结构、布尔值和数量，不记录正文、文件名标签或文件内容。

## 验收

智能体仅运行 `npm run build`。以下检查由用户运行，智能体读取日志。

1. 离线检查：`node tools/diag/read-files-check.cjs`。覆盖实际日志中的三个文件输入框、通用入口优先、输入区域范围与多文件限制，以及路径协议与旧参数兼容、完整附件字节、限额、部分错误、快照、SSH 路由、取消、两个平台的 CDP 文件选择与单次提交。ChatGPT 检查覆盖采集到的完整用户消息容器、文字单元缺失／重建、旧容器重绘、容器节点复用、新消息重命名卡片、嵌套节点归并、正文之外的文件／图片卡片、title／aria-label 文件名、无扩展名文件以及旧消息／模型答复／输入框的边界。DeepSeek 检查还覆盖禁用按钮、文件名卡片、数字／非数字混合标识、旧行重新渲染、思考行排除和同一 DOM 行的复用；调用实际命令检测函数，检查确认结束后只报告一次下一条命令、保留旧消息去重和未发送草稿，并遵守终端关闭／历史恢复状态。这些模拟检查不能证明真实网页可用。
2. 运行 `npm run dev`，分别试文本／源码附件、图片、PDF、手动模式、自动模式、暂停恢复、结束任务、已有草稿、切换会话和 SSH 断线。确认消息仅含附件，没有读取结果、路径、内部标记或正文摘录；全部读取失败时错误只出现在本地执行记录。DeepSeek 在自动模式中测试「读取文件 → 附件发送 → 模型返回下一条命令」，检查下一条命令自动执行且附件只发送一次。重复上传同一图片、快速返回下一条 AI 请求和旧消息重新渲染时也需检查发送确认状态。
3. 如附件入口或上传状态不被识别，关闭项目后运行 `node_modules\electron\dist\electron.exe tools\diag\attachments-probe.js deepseek`（ChatGPT 时省略末尾的 `deepseek`）。手动上传并发送无敏感内容的图片和文档，再关闭窗口。探针读取应用的实际适配器，日志包含祖先结构、附件输入、进度语义、按钮禁用状态和消息行位置，不自动发送。
4. 分别打开两个提示词查看入口：基础视图不含工具说明，ChatGPT 和 DeepSeek 的工具视图均显示 `read_files` 并使用当前平台名称；复制和 Ctrl+F 仅作用于当前视图。切到未适配平台后，工具视图显示暂无内容。修改机器补充说明后，基础视图和下一条消息的注入内容同步更新。

离线检查和探针日志位于 `%TEMP%\gpt-login-diag\`。附件探针不自动选文件、不自动上传、不自动发消息，只观察输入框、文件输入、附件预览和按钮状态。不记录文件内容、图片字节或 cookie 值。

网页里已经有文件卡片、但日志始终没有识别出新用户消息时，可运行 `node_modules\electron\dist\electron.exe tools\diag\attachments-probe.js --file-name hosts`。打开原先失败的会话，保留卡片可见并等待 10 秒。探针会独立从文件名匹配叶节点反查祖先和附近 DOM 结构，不依赖现有消息选择器；也可手动上传终端打印的无敏感测试文件，采集上传、发送、模型回复前后的变化。模型回复结束后再等 10 秒，关闭探针窗口。新增 `messageStructure` 记录标签、类名、属性名／长度、角色标记、节点／标识别名与计数，不记录聊天正文、标签文本、链接值或原始消息标识。

当前附件发现使用现有输入框选择器和通用 HTML 文件输入、图片、进度条结构；附件菜单延迟创建输入框、页面结构变化、上传被网页拒绝、DevTools 占用调试连接都可能导致回传失败。这些真实网页行为需用户测试确认，构建成功不代表附件发送已验证。
